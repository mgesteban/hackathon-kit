# Pre-demo checklist

Hackathon / demo readiness. Run this end-to-end the day before the demo, not the morning of. Every item exists because something has failed once.

## Demo path

- [ ] One-line pitch written down and rehearsed out loud at least 3 times.
- [ ] Demo script: the exact sequence of clicks / commands / questions you'll run, in order, in writing.
- [ ] **Run the full demo path on the actual demo machine**, not just your dev laptop. Different OS, different network, different fonts.
- [ ] Stopwatch the demo. If you have a 3-minute slot, the path must fit in 2:30 with room for one thing to go wrong.

## Backup plan

- [ ] Backup video of the full demo recorded (OBS, Loom, QuickTime). Saved locally AND uploaded somewhere reachable.
- [ ] A "reset" or "fresh state" mode so you can re-run the demo back-to-back without leftover data.
- [ ] If the demo depends on a live external API: a recorded happy-path video as fallback when the API is down.

## Infrastructure

- [ ] Live API keys not expired. Test every external API one final time — don't trust "it worked yesterday."
- [ ] Database has the seed / sample data the demo needs, and a script to re-seed if it gets nuked.
- [ ] Deployed URL works from a fresh browser (no cached login, no extensions). Use an incognito window.
- [ ] Mobile hotspot ready as network fallback. Test it actually works at the venue if possible.

## Visuals & presentation

- [ ] Slides / repo URL ready on a second tab or device — not buried inside the IDE.
- [ ] Spelling of org name, judges' names, partner companies double-checked.
- [ ] Browser zoom level set so the back row can read it.
- [ ] Notifications silenced. Slack, email, Discord, calendar reminders — all off.
- [ ] Battery charged and charger packed.

## Story

- [ ] Problem stated clearly in the first 20 seconds (who is hurting, why, how much).
- [ ] Why-now stated (what's new that makes this possible).
- [ ] The "wow moment" of the demo is rehearsed so it lands — not muffled by you talking over it.
- [ ] Ending line written down so you don't trail off.

## Day-of

- [ ] Arrive at the venue with the demo already loaded and running locally.
- [ ] Run the full demo once at the venue before judges arrive.
- [ ] If a hardware demo: bring spares of anything plug-shaped.

## After the demo

- [ ] Capture what went well, what failed, and what surprised you while it's fresh.
- [ ] If a lesson generalizes beyond this app, update the app-starter skill or write a feedback memory.
